# Git Lens Web 桌面版：Electron 产品开发指南与执行计划

> 状态：待执行的工程方案。基线为 `main@1cc3e1f`（2026-09-27）；方案在独立协调分支 `codex/electron-coordination` 编写。本文不代表桌面版已经实现或验收。

## 1. 目标、范围与交付定义

目标是交付可安装、可升级、可诊断的 Git Lens 桌面应用，保留现有浏览器运行方式。桌面版应完整覆盖仓库总览、Worktree 与分支管理、Diff、提交记录、stash、本地 MR 等现有能力，并提供原生目录选择、应用菜单、窗口状态恢复、Git 环境诊断和安装包。

正式交付必须同时满足：

1. 功能清单和 UI 清单逐项有自动化或人工验收证据，没有未完成项。
2. 目标平台安装包在对应操作系统上完成首次安装、重启、升级、卸载与异常恢复验证。
3. 所有 P0/P1/P2 缺陷关闭；已知 P3 缺陷逐项评估并记录，不能把“未测到”写成“无缺陷”。
4. 全部测试仅操作脚本新建的临时 Git 项目、专用配置和专用应用数据目录；保留主实例 `9527` 与真实配置原样。
5. 协调分支通过完整合并验收后，才创建面向 `main` 的唯一交付 PR。未经该门禁，不向主线合并。

首版目标矩阵暂定 macOS（arm64、x64）、Windows（x64）和 Linux（x64）；具体最低系统版本、分发渠道、签名证书、更新服务器由 G0 冻结。未取得某平台的真实安装与验收环境时，该平台标记“未验收”，不列入已交付范围。

## 2. 仓库基线与需要处理的边界

| 现状 | 桌面化影响 | 处理阶段 |
| --- | --- | --- |
| `src/server.js` 导入时立即监听 `127.0.0.1:9527`，配置目录由环境变量或默认用户目录决定 | Electron 直接导入会抢占主实例端口，并可能读取真实配置 | G1 拆分服务工厂与 CLI 入口 |
| `public/index.html` 使用相对 `/api/*` 请求 | 可以复用页面和 API，但窗口来源、状态恢复与安全策略必须验证 | G2、G4 |
| `src/git-inspector.js`、`src/merge-request-service.js` 调用系统 `git` | 安装包不自带 Git 时，需要跨平台发现与故障提示 | G2、G5 |
| API 统一发送 `Access-Control-Allow-Origin: *`，包含删除、合并等写接口 | 需完成全 API 本地访问边界和请求体限制，不能只校验目录选择接口 | G1、G3 |
| `public/index.html` 有内联脚本和大量动态 HTML | 严格 CSP、恶意 Git 元数据转义和 Electron 沙箱需要联合处理 | G3、G4 |
| 现有 `scripts/mr-diff-fixture.sh` 会重建传入目录的 fixture 子路径；`scripts/verify-mr-branch-diff.mjs` 接受任意 URL，且会读取真实配置目录的元数据 | 原脚本不得原样用于桌面版最终验收；先加拒绝生产环境的保护 | G0、G4 |

桌面壳应复用现有 API 业务逻辑。`npm start` 继续保持浏览器模式与默认 `9527` 端口，不改变现有用户的启动方式和配置语义。

## 3. 目标架构与关键契约

```text
Electron 主进程
  ├─ 单实例锁、应用菜单、窗口和原生目录选择
  ├─ 监督独立的本地服务进程，接收就绪/异常/退出事件
  ├─ 维护只在主进程保存的本地 API 会话凭据
  └─ 创建受限 BrowserWindow，加载 127.0.0.1 的随机端口
         │
         └─ 现有页面和 /api/* 请求

本地服务进程
  ├─ 复用现有 HTTP 路由与 Git/MR 模块
  ├─ 仅监听 127.0.0.1 的系统分配端口
  └─ 仅使用桌面版专用配置目录
```

### 3.1 服务生命周期

将 `src/server.js` 分成无监听副作用的服务工厂和浏览器 CLI 入口。建议导出 `createServer({ configDir, chooseDirectory, auth, ... })` 与 `startServer({ host, port, ... })`；`port: 0` 返回实际监听地址。不得通过导入现有 `server.js` 启动桌面服务。服务应提供可等待的就绪和关闭结果，端口占用、Git 缺失、配置读取失败均产生可展示的中文错误。

Electron 主进程优先监督独立服务进程（`utilityProcess` 或经打包实测可用的 `child_process.fork`）。服务就绪后创建/加载窗口；窗口刷新不重启服务；服务意外退出时展示恢复页、记录诊断信息，并限制自动重启次数；应用退出时请求正常关闭、等待退出，超时才终止。通过单实例锁把第二次启动转为激活已有窗口。正式发布前验证无孤儿服务、无重复监听、崩溃后可恢复。

### 3.2 配置与迁移

浏览器模式继续使用 `~/.config/git-lens-web` 或显式 `GIT_LENS_CONFIG_DIR`。桌面版使用 Electron `app.getPath('userData')` 下的独立配置路径，支持从既有 Web 配置**读取预览、确认后复制**扫描目录与本地 MR 数据；迁移须原子写入、保留备份、记录版本、可重试和回滚。测试时强制把 `userData`、服务配置和 Git 全局配置都指向同一轮测试的临时目录。不得在测试中读取、比较或修改真实用户配置。

G0 冻结配置版本、迁移字段及路径格式。迁移测试仅使用自建的旧版配置样本，覆盖目录不存在、损坏 JSON、权限不足、重复迁移和旧版 MR 数据。

### 3.3 本地 API 安全

桌面服务只绑定环回地址，使用随机端口。所有 API 包括只读接口均执行 Host、Origin/来源和每次启动会话凭据校验；拒绝 DNS rebinding、跨站请求、缺少或错误凭据的请求。浏览器模式保留可用性，同时移除宽松 CORS，明确允许本机页面来源。对 JSON 请求体设大小上限与超时，逐个审查文件读取、Git 路径和写操作参数的边界。重点复核 `/api/raw-file` 的工作区路径与仓库路径关系。

桌面凭据只由主进程持有；若继续用 HTTP `fetch`，由受控的 Electron 请求钩子为该窗口的同源请求附加凭据，不把令牌暴露成页面全局变量。即便如此，页面中的 XSS 仍可能借窗口发起操作，因此 G3 必须完成动态 HTML 转义审计、恶意文件名/提交信息测试和可实施的 CSP。不得把 `nodeIntegration` 当成业务功能开关。

`BrowserWindow` 采用 `nodeIntegration: false`、`contextIsolation: true`、`sandbox: true`。preload 仅暴露必要且有参数校验的原生能力；禁止任意 Node、shell 或 IPC 通道。拦截外部导航、新窗口和下载；需要打开外部链接时由主进程检查协议和目标后调用系统浏览器。权限请求默认拒绝，确有需求时按来源逐项开放。

### 3.4 原生体验与 Git 依赖

目录选择改为 Electron 原生 `dialog.showOpenDialog()`，浏览器模式继续保留现有系统选择器。原生菜单至少覆盖刷新、返回/前进、缩放、复制、帮助和退出；快捷键需符合平台习惯。窗口尺寸、位置和上次选中仓库可以恢复，但必须处理显示器移除后的越界位置。

首版明确依赖系统 Git：启动时发现可执行文件、显示版本，并在未找到 Git、权限不足或 Git 命令超时时给出操作建议。macOS 图形应用的 PATH、Windows 安装路径、Linux 桌面启动环境分别测试。是否内置 Git 留待后续版本评估。

## 4. 协调分支与多 worktree 并行执行

### 4.1 分支拓扑

协调分支固定为 `codex/electron-coordination`，对应独立 worktree，不在主仓库 checkout 或测试。所有任务分支从协调分支一个已通过门禁的提交创建；协调分支是唯一集成入口。若 Codex 托管 worktree 工具可用，先用该工具创建并挂载，再在新 worktree 建任务分支；只有工具不可用时才手工 `git worktree add`。已有 `codex/readme-refresh` worktree 不参与本计划。

| 工作流 | 分支 | 独占文件/职责 | 进入条件 |
| --- | --- | --- | --- |
| 协调 | `codex/electron-coordination` | 契约、`package.json`/lockfile、集成、统一验收、交付 PR | 已建立 |
| Runtime | `codex/electron-runtime` | `src/server.js` 拆分、服务生命周期、配置注入、API 访问边界 | G0 契约冻结 |
| Shell | `codex/electron-shell` | `electron/**` 主进程、preload、原生目录选择、窗口、Git 诊断 | Runtime 接口冻结 |
| UI | `codex/electron-ui` | `public/**` 页面适配、加载/错误/恢复界面、桌面交互 | Runtime 与 preload 契约冻结 |
| QA | `codex/electron-qa` | `test/**`、安全 fixture、Electron E2E、视觉基线与测试守卫 | G0 测试协议冻结 |
| Release | `codex/electron-release` | `assets/**`、打包/签名/更新配置及发布文档 | Shell 可打包后 |

协调 Agent 同时最多带三个执行 Agent，以匹配当前四个并发槽位。先由 Runtime 与 QA 准备基础契约和安全测试；Runtime 合入并通过 G1 后，以同一协调 HEAD 派发 Shell、UI、QA 并行实施。Release 在 Shell 稳定后接续空出的槽位。跨工作流改同一个文件前，提交接口变更申请，由协调 Agent 修改契约并通知相关 Agent；禁止两个 worktree 同时编辑 `src/server.js`、`public/index.html` 或 lockfile。

### 4.2 每个 Agent 的交付包

每个执行 Agent 交付：中文提交信息、提交 SHA、改动文件清单、契约差异、测试命令及原始结果、fixture run-id、UI 截图/录屏、已知问题和风险。提交遵循 `AGENTS.md` 的“英文 type + 中文动宾描述”；功能、文档、修复按职责拆提交。工作树需清洁，不能把临时配置、测试仓库、安装包或签名密钥提交到仓库。

协调 Agent 检查文件所有权和契约后，按 Runtime → Shell → UI → QA → Release 顺序 `merge --no-ff` 到协调分支。每次合并都在新的协调 HEAD 上运行对应单元测试和隔离集成测试；达到 G4 后每次合并还需运行全量 Electron E2E 与 UI 回归。发生冲突时在协调分支 `git merge --abort`，把当前协调 HEAD 和冲突文件清单回派原 Agent，让其在原 worktree 更新并解决，再重新提交。协调分支不直接热修业务缺陷，避免修复与所有权分离。

### 4.3 失败回派闭环

```text
执行 Agent 提交 → 协调分支合并 → 创建全新 fixture 验收
      ↑                                │
      └── 原 Agent 在原 worktree 修复 ← 失败：记录缺陷并按文件所有权派回
                                       │
                                       └─ 通过：下一工作流/下一门禁
```

每个缺陷记录编号、严重级别、协调 HEAD、操作系统与架构、fixture run-id、复现脚本或步骤、预期/实际、截图或日志、责任 worktree。一个缺陷涉及多个工作流时由协调 Agent 指定一个主责任者，其余 Agent 配合，避免互相等待。修复在原任务分支提交并先跑本分支测试，再增量合入协调分支；协调 Agent 使用**全新** fixture 重跑失败项、受影响项和全量回归。未通过则继续回派，循环直到门禁通过。除非用户明确改变目标，不以时间或迭代次数代替验收结果。

主线有新提交时，先将 `main` 并入协调分支，重新执行完整门禁；任务分支只跟随协调分支。执行分支不得直接合入 `main`。最终由协调分支建立唯一 PR，PR 描述列明目标平台、验收证据、未覆盖范围和迁移风险。正式发布后的修复另起补丁分支，不改写已发布历史。

## 5. 分阶段里程碑与明确门禁

| 门禁 | 交付物 | 必须通过的验收 |
| --- | --- | --- |
| G0 契约与隔离基础 | 支持平台矩阵、服务/IPC/配置契约、文件所有权、fixture 生成器和防误用守卫 | 测试脚本误传 `9527`、真实配置或非 fixture 路径时在任何写操作前失败；记录基线测试结果 |

| G2 桌面壳 | 单实例、窗口、preload、目录选择、Git 诊断、服务进程监督 | 首启、刷新、退出、重启、二次启动、服务崩溃恢复、无 Git、无残留进程 |

| G4 功能与 UI | 全功能桌面适配、E2E 和视觉基线 | 第 7 节矩阵全部通过；目标窗口尺寸、缩放、键盘操作与原生弹窗无缺项 |
| G5 安装与升级 | 各平台安装包、签名/公证方案、更新与迁移、诊断日志 | 对应 OS 干净环境真实安装、首次运行、升级、回滚、卸载；包内 Git 路径与服务进程正常 |
| G6 合并验收 | 协调分支最终报告与交付 PR | 从全新 fixture 执行全部门禁；P0/P1/P2 为零；UI/功能清单全覆盖；证据可复核 |

估算以 3 个执行 Agent 并行、目标平台测试机和签名条件及时到位为前提：G0–G2 约 1 周，G3–G4 约 1–2 周，G5–G6 约 1 周。多平台签名、更新服务器或系统权限问题会改变实际工期；门禁失败不按日期放行。

## 6. 自建测试项目与绝对隔离协议

### 6.1 每轮独立测试根目录

每轮用 `mkdtemp` 在系统临时目录新建根目录，例如 `/tmp/git-lens-electron-qa-<run-id>/`，并通过 `realpath` 固定根路径：

```text
<qa-root>/
  repos/                 测试 Git 主仓库与 worktree
  config/                GIT_LENS_CONFIG_DIR
  electron-user-data/    Electron userData
  git-home/              HOME、XDG_CONFIG_HOME、GIT_CONFIG_GLOBAL
  artifacts/             截图、日志、测试报告
  manifest.json          run-id、允许路径、端口、版本、SHA
```

fixture 包含干净/脏 Worktree、staged/untracked 文件、已合并/未合并/失联分支、stash、cherry-pick 与 squash 吸收、冲突 MR、二进制与图片、中文/空格/特殊字符路径、恶意文件名与提交信息。Git 作者和系统/全局配置同样隔离。每轮运行生成新 fixture，不复用上轮状态；测试结束只清理此轮经 manifest 确认的根目录。失败时保留脱敏的报告和必要 fixture 快照供复现。

### 6.2 写操作前的 fail-closed 守卫

统一测试启动器必须在**发出第一个 HTTP 请求前**完成以下检查：

1. `base-url` 只允许 `http://127.0.0.1:<非 9527 端口>`，禁止域名、转发代理和 `localhost` 自动解析；本 worktree 的手工 Web 联调用 `9528`，先确认旧监听进程已经退出，且配置为 `/tmp/git-lens-web-dev-9528`。并行 worktree 使用彼此不同的非 9527 端口和 `/tmp` 私有配置。
2. `GIT_LENS_CONFIG_DIR`、`userData`、扫描目录、所有 Git 写操作目标经 `realpath` 后都必须位于本轮 qa-root 内；拒绝符号链接逃逸、空值、默认用户配置和仓库源码目录。
3. 服务以显式测试模式启动，并在仅测试模式启用的握手接口返回 run-id、fixture 根目录和配置根目录；客户端核对与 manifest 完全一致。普通 `/api/projects` 成功不算身份验证。
4. 启动时扫描目录必须为空或只包含本轮 fixture 路径；任何异常立即停止，不尝试“清理”未知配置。
5. Electron E2E 覆盖 `userData` 和服务配置；启动日志须记录实际随机端口与 run-id，确认不等于 `9527`。不得读取或 `stat` 真实配置作为隔离证明。

现有 `scripts/mr-diff-fixture.sh` 可复用素材，但它会删除并重建传入目标目录下若干子路径，只能在新建且经守卫确认的 qa-root 子目录执行。现有 `scripts/verify-mr-branch-diff.mjs` **不能原样用于最终验收**：其任意 `--base-url` 和先请求 `/api/projects` 的行为不能阻止误连生产实例，且脚本会读取真实配置元数据。G0 先将其改为经过 run-id 握手、拒绝 `9527`、拒绝非环回地址、只读私有配置的 fail-closed 版本；改好前不得运行该脚本测试桌面版。既有 `node --test test/*.test.mjs` 可以作为低层回归起点，但需审核每个测试的临时路径与进程退出清理。

### 6.3 验收命令约定

由 QA 工作流提供单一入口，例如 `npm run test:desktop:isolated`：自动建 fixture、注入专用环境、启动服务/桌面应用、执行全部测试并生成报告。协调 Agent 只调用这个入口或它明确定义的阶段参数，不手工指定任意真实仓库路径。底层 HTTP 测试必须从已握手的测试启动器获得地址；Electron E2E 从主进程读取就绪信息，不能猜测端口。任何测试进程退出都检查服务是否已结束、端口是否释放、`9527` 主实例和真实配置未被触碰的证据来自进程与测试 manifest，而非读取真实配置内容。

## 7. 功能、UI、安全与发布验收矩阵

| 领域 | 必测场景 | 证据 |
| --- | --- | --- |
| 启动与生命周期 | 首启设置、窗口刷新、关闭/重开、单实例、服务崩溃、配置损坏、无 Git、权限不足、随机端口 | Electron E2E、服务日志、进程/端口快照 |
| 仓库总览 | 自建扫描目录增删、空态、多仓库搜索与收藏、刷新、失联 Worktree、领先/吸收状态 | E2E 截图、API 断言 |
| Diff 与提交 | Worktree/分支各组合、三种模式、未提交/未跟踪、图片/二进制、长列表、提交过滤和详情、URL/会话恢复 | E2E、fixture 的 Git 结果、视觉截图 |
| 写操作 | 分支和 Worktree 清理、prune、stash 全动作、Cherry-pick/Revert、MR 审阅/合并/冲突回滚 | 操作前后 `git status`、ref、worktree 列表和 MR 存储断言 |
| 原生 UI | 目录对话框、菜单/快捷键、复制、外链、错误与恢复页、系统深浅色、100%/125%/150% 缩放、窄窗口与多显示器 | 各平台截图、键盘操作记录、视觉差异审阅 |
| 安全 | 跨 Origin、错误/缺少凭据、DNS rebinding、恶意 Git 文本、路径逃逸、大请求体、外部导航、渲染进程 Node 禁用 | 自动化拒绝断言与安全审计记录 |
| 安装与迁移 | 干净系统安装、首启、旧版自建配置迁移、升级、回滚、卸载、保留/移除用户数据选择 | 对应 OS 的安装记录、签名验证、配置比对 |

UI 验收按“页面 × 状态 × 平台 × 尺寸”建立可勾选清单，至少覆盖总览、Diff、本地 MR 三个主视图，以及每个抽屉、弹窗、空态、加载态、错误态和确认操作。截图自动比对只能提示偏差，最终由协调 Agent 逐项审阅，确认无截断、遮挡、失焦、不可点击、文字溢出或功能入口缺失。所有写操作均需在自建 Git 项目中完成端到端验证，不能只凭 API 返回 `ok: true`。

缺陷等级：P0 为数据丢失、越界写入或生产环境误触；P1 为核心流程不可用、安全边界失效或安装/启动失败；P2 为明确的功能/UI 缺失、错误结果或恢复失败；P3 为不影响完成任务的轻微表现问题。G6 要求 P0/P1/P2 清零、P3 有审阅结论；任何安全隔离失败直接停止所有后续写测试。

## 8. 发布、回滚与维护

锁定 Electron 和打包工具版本，生成可复现的 lockfile；发行包中不包含测试 fixture、源码临时目录或密钥。macOS 完成签名、公证与 Gatekeeper 验证；Windows 完成签名与 SmartScreen 分发方案；Linux 验证目标发行版安装与桌面启动。自动更新仅针对已签名发布渠道启用，更新清单和包校验失败时不得替换当前可用版本。

升级前备份自建样本配置，验证从上一正式版到新版的迁移、失败恢复和回滚。日志只记录必要诊断信息，避免收集仓库源码、Diff、令牌及凭据。最终验收报告明确各平台包的 SHA、签名结果、测试机系统版本、功能/UI 清单、失败修复轮次及未覆盖范围。完成后将协调分支交付为唯一 PR，由用户审阅合并和发布安排。

## 9. 立即执行的首批任务

1. 协调 Agent 冻结 G0 契约、支持平台与验收 manifest 格式，记录 `main@1cc3e1f` 基线测试。
2. QA Agent 先实现测试启动器的 fail-closed 守卫和自建 fixture，修复既有验证脚本误连生产的风险。
3. Runtime Agent 拆分服务工厂与 CLI 入口，在私有配置、随机端口上跑现有 API 回归。
4. G1 通过后创建 Shell、UI、QA 并行 worktree，按第 4 节的文件所有权和交付包持续合并。
5. 按 G2–G6 门禁反复合并、验收、回派修复，直到功能与 UI 清单全部通过，再创建交付 PR。
